**Feat: a score module declares what it produces, and the host picks one per kind (vivijure-cf#878).**

The `score` hook carries three products a film can use together: a music bed, narration and a beat plan. It was declared `chain`, and hosts picked a single module by sniffing config keys (`prompt` for music, `text` for narration, `clip_seconds` for beat). Now each score manifest declares new optional `score_kind`: `"music"`, `"narration"` or `"beat"`. New `pickScoreModule(modules, kind, choice?)` (`@skyphusion-labs/vivijure-core/modules/score-select`) picks one module within a kind, an explicit choice first and then `ui.order`, and every refusal names its cause: not installed, the wrong kind, or no kind declared. A score module that declares no kind is never selected and is named in the refusal. `checkManifest` fails conformance for it while `validateManifest` still loads it, the same split as `participation`. A malformed `score_kind` does not load.

`HOOK_CARDINALITY.score` is the new value `pick_one_per_kind` (type `HookCardinality`; `HookCatalogEntry.cardinality` widens to it). `resolveRenderPipeline` returns one score module per kind, and takes `score_choice: { music?, narration?, beat? }`. Core's `beatSyncScoreModules` selects by kind `beat`, not by a `clip_seconds` key. The `audio:<key>` applied tag is unchanged. New exports: `HookCardinality`, `SCORE_KINDS`, `ScoreKind`, `pickScoreModule`, `scoreModulesOfKind`, `undeclaredScoreModules`, `ScorePick`.

**Deploy order.** Score modules must declare `score_kind` before a host on this release selects them; a host on this release ignores an undeclared score module and says so.
