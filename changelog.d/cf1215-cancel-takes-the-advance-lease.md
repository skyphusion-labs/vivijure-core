**Fix: a cancel can no longer be undone by a tick that wrote back an older film doc (vivijure-cf#1215).**

A tick reads the film doc, works, and writes it back, under the advance lease. `cancelFilmJob` wrote the doc with no lease, so a tick that read the doc before a cancel could write it back after, and the film kept spending with `cancelled` lost. The studio's R2 retry made one case of this easy to reach: a tick's put that lands and errors is put again, up to about 4 s later, over the cancel. `cancelFilmJob` now takes the same lease. It waits up to `FILM_CANCEL_WAIT_MS` (20 s), asking every `FILM_CANCEL_CLAIM_EVERY_MS` (1 s), for a running tick to let go, and then throws `FilmBusyError` without writing anything or asking any job to stop. A film already terminal is returned unchanged even while a tick holds it. Like a tick, the cancel fails open on a D1 error. New exports: `FilmBusyError`, `CancelFilmOptions`, `FILM_CANCEL_WAIT_MS`, `FILM_CANCEL_CLAIM_EVERY_MS`. `cancelFilmJob` takes an optional third argument. A host should answer `FilmBusyError` as a retryable conflict (409).
